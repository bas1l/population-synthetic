The `config/` inventory: what each config tree holds and which code reads it.

- **Seed manifests:** `config/synthetic/manifests/` -- YAML files that bundle all identity generation settings (provider, model, mode, config, strategy, parallel params) into a single file. Loaded via `--manifest` flag. CLI args override manifest values when both are provided.
- **Simulation configs:** `config/synthetic/simulation_configs/` -- per-attribute `categories` schema + locale `instruction` system prompt for configurable mode. Strategy definitions are single-file yamls under `config/synthetic/axes/strategies/` (see [Axis composition](axis-composition.md)).
- **SCB API cache:** `config/database/caches/scb/` (git-ignored)
- **SSB API cache:** `config/database/caches/ssb/` (git-ignored)
- **Eurostat API cache:** `config/database/caches/eurostat/` (git-ignored)
- **ISTAT API cache:** `config/database/caches/istat/` (git-ignored)
- **Category label mappings:** `config/mapping/{scb,istat}/` -- the unified symmetric comparison config: one JSON file per comparison attribute (filename stem == top-level key) declaring `values`/`real`/`synthetic`, plus an `_index.json` master (`attribute -> filename` in axis order -- attributes only). The loader (`load_mappings`/`load_index` in `analysis/mapping/real_mapper/mappings.py`; `analysis/mapping/normalizer.py` re-exports `load_mappings`) merges every `*.json` in a country directory into a single dict keyed by stem (it also still accepts a single monolithic file). Both mapper sides and the comparison scheme are driven entirely by this config -- see [Comparison & mapping](comparison-mapping.md) and each dir's `README.md`. The cross-attribute comparison statistics (`joint_pairs`/`coherence_attributes`/`coherence_threshold`) are **not** here -- they live in `config/analysis/fidelity/{scb,istat}.json` (see `analysis/fidelity/scheme.py`). (`config/mapping/ssb/` is legacy Norway config, not wired into the comparison scheme mechanism.)
- **Axis configs:** `config/synthetic/axes/models/`, `config/synthetic/axes/strategies/`, `config/synthetic/axes/countries/` -- YAML files composable via `--model-id`, `--strategy-id`, `--country-id`. A country YAML carries `id`, `label`, `parameters.config` (pointing at a simulation config JSON), plus `parameters.reference` (real-population path; the YAML key itself is unrenamed pending a follow-up config-layer rename) and `parameters.mappings` (mappings dir) consumed by the comparison pipeline's `analysis/utils/country_config.py`. It also carries `display.reference_source`, the short name of the agency the real population comes from (`SCB` for `swedish` / `swedish_02`, `ISTAT` for `italian`), read by `analysis/utils/labels.py::reference_source`, which raises when it is absent; it is provenance only, never a figure label (figures call the real population by `figure_term("reference")`). `swedish` -> `simulation_config_004_swedish_generative.json`, `italian` -> `simulation_config_005_italian_generative.json`; each simulation config carries a locale-specific `instruction` system prompt and per-attribute `categories`
- **Experiment defaults:** `config/synthetic/experiment_defaults.yaml` -- base parameters including `output_base` path
- **Analysis registry:** `config/analysis/analysis_registry.yaml` -- the single source of truth for the analysis layer: the two stage-folder literals `stage_dir` (`03_Analysis`) and `figures_stage_dir` (`04_Figures`), plus one entry per process mapping its **canonical id** -> `{label, description, stage, folder, script, dispatch}` (optional `legacy_folder` for back-compat reads). The id is simultaneously the registry key, the GUI workflow task key, and the `03_Analysis/` output-folder name. `stage` selects which stage folder the process writes into and is **optional -- its absence means `analysis`** (the documented default carried by all 17 analysis processes); a present-but-blank or unknown value raises rather than being defaulted away. `folder` is conditional on it: required for an `analysis`-stage process, forbidden for a `figures`-stage one (`figure_selection`), which owns the figures stage root itself. Loaded fail-fast by `analysis/utils/registry.py` (missing file / missing required key / unknown id raises), which exposes `get_process`, `analysis_output_dir(id, base, *, for_read=False)` (raising if handed a figures-stage id), `figures_output_dir(base, *, country, set_name, naming)`, `resolve_output_base`, and `ANALYSIS_STAGE_DIR` / `FIGURES_STAGE_DIR` -- the only place in code either stage literal is defined; consumed by BOTH the analysis scripts and the GUI workflow model (`WorkflowConfigModel.get_task_meta`). The `mapping` entry sets `folder: mapping` with `legacy_folder: mapped` so readers fall back to any legacy on-disk `mapped/` until re-mapped.
- **Figure roster:** `config/analysis/figure_selection.yaml` -- which figures get published out of `03_Analysis` into `04_Figures`, and under which manuscript number. `sets:` maps a set name (`manuscript`, and any other purpose a run selects with `--set`) to an ordered list of entries, each `{n, name, source}` plus an optional `slug: {model, strategy}` block: `source` is an **extension-less stem** relative to the analysis stage whose first segment must be a registry process id, `n` is the manuscript figure number (unique within the set, and what orders and names `numbered/`), and `name` is the filename slug beside it. Two placeholders only -- `{country}`, the run's country id, and `{slug}`, available only to an entry declaring a `slug:` block and composed through `manifest_loader.axis_slug` -- so a stem stays portable across countries and cannot disagree with the folder name the producing task wrote; a segment that is neither is written out as a literal. Nothing is auto-discovered: a figure is in a set because a human listed it. Loaded fail-fast by `analysis/figure_selection/config.py` -- everything decidable without a country raises there, before any filesystem work: unknown set, unregistered process id, unknown placeholder, `{slug}` without a `slug:` block or vice versa, duplicate `n`, repeated `source`. The country-dependent checks (a stem with nothing behind it, a partial format set, two entries resolving to the same `as_generated` basename) belong to `analysis/figure_selection/resolve.py` and still run before the first copy. Consumed by `scripts/analyze/select_figures.py`.
- **Comparison targets:** `config/analysis/comparison_targets.yaml` -- the explicit completeness list consumed by the map stage (`scripts/analyze/map_populations.py`). `targets:` is a list of entries, each either a plain manifest-path string (country inferred from the simulation-config filename) or a `{manifest, country}` mapping (explicit country override). The map stage processes only these targets -- it does not scan disk.
- **Figure terms:** `config/analysis/figure_terms.yaml` -- the manuscript-controlled words a published figure prints that are neither an axis id nor an attribute, under `terms:`: `individuals`, `strategy_key_title` ("Strategies") and `reference` ("Reference"). They live in config because the manuscript's terminology rules (T1: *individual*, not persona; *strategy*, not method; the real population is *the reference*) govern published artwork while code identifiers, CSV columns and JSON keys keep the repository's own words. Read by `analysis/utils/labels.py::figure_term(key)`, which raises on a missing file, an unknown key, an empty value or one containing an underscore -- no fallback to the key. Today only `realism_ranking`'s typicality distribution grid reads it.
- **Typicality closeness resampling:** `config/analysis/realism_ranking/typicality_closeness.yaml` -- the single source of truth for the resampling settings of `realism_ranking`'s `typicality_closeness` block: `ci_level`, `bootstrap_iterations` / `bootstrap_seed` (the joint individual-level bootstrap every interval in the block comes from), `permutation_iterations` / `permutation_seed` (the within-block permutation test), and `noise_iterations` / `noise_seed` / `noise_quantile` (the reference self-resampling noise baseline). Read fail-fast at the CLI edge by `scripts/analyze/rank_persona_realism.py` (every key required, an unknown key raises, no in-code default), passed to the builder verbatim, and stamped into `realism_ranking.json` as `provenance.closeness_resampling`. The `typicality_effects` intervals use the judge config's own `bootstrap` block instead (`config/analysis/persona_realism/`).
- **Model-ranking provider hosting:** `config/analysis/model_ranking/provider_hosting.json` -- a `{"providers": {provider -> "local"|"hosted"}}` map grouping each identity-generation provider (`model_config.provider` on the model axis YAMLs: `ollama`, `claude`, `gemini`, `openrouter`, `openai_compat`) into a hosting/provenance class (`ollama` -> `local`, the rest -> `hosted`). Loaded by `analysis/model_ranking/hosting.py` and embedded at `metadata.model_hosting` in the performance JSON so the manuscript tables can encode provenance by hue. `rank_persona_realism.py` classifies with the same file to tint the typicality distribution grid's column labels and ternary points. Every provider must appear here -- an unknown provider fails loudly (no default class), per the fail-fast rule.
- **Ollama host registry:** `config/synthetic/ollama_hosts.yaml` -- the single authoritative list of Ollama inference endpoints: `default_host` (used only when `--ollama-host` is omitted) plus a `hosts:` mapping of **host id** -> `{label, base_url, gpu, server_num_parallel}` and the optional `control_url`. The host id is the only identifier that appears in CLI flags, GUI config, the model axis files' per-host `parameters.parallel.workers` map, and run provenance -- never a hostname or a URL. `server_num_parallel` is the human-declared `OLLAMA_NUM_PARALLEL` of that host's Ollama process: it is **not** a worker count and is never used as one (warning threshold only; Ollama exposes it on no endpoint, so the code cannot verify it). `control_url` is the **optional** endpoint of that host's `:11435` control service, which is the only way `OLLAMA_NUM_PARALLEL` can be changed over HTTP (it recreates the container); it is not a required key, so a host declaring none still loads and runs -- `--ollama-reconfigure` simply records `no_control_url` for it. When present it is shape-validated (non-empty string, `http://` or `https://` scheme) and raises naming the host id and the file otherwise. Loaded fail-fast by `generators/synthetic/ollama_hosts.py` (`load_hosts` / `resolve_host` / `host_ids`): a missing file, malformed YAML, an empty `hosts` block, a host missing a required key, a `default_host` naming no declared host, or an unknown host id all raise -- there is no default base URL anywhere in code, so no run can be dispatched to an unintended GPU.
- **Model pricing table:** `config/analysis/model_pricing.yaml` -- the single source of truth for the `generation_metadata` cost model, consumed by `analysis/generation_metadata/pricing.py::load_pricing_table`. USD per 1,000,000 tokens, keyed by the model **axis id** (the same id used in run slugs / `discover_axis_values("models")`) so the join to a generation combo is exact: `models: {<axis_id>: {in: <price>, out: <price>}}`, with top-level provenance stamps `observed_date`, `source`, and `currency` carried verbatim into the analysis JSON. `ollama_*` models are priced at a genuine `0`. The prices are a static, dated snapshot (not fetched live); rows carry `[VERIFY]` / "effective/discounted" comments to check before publication use. Loaded fail-fast (missing file / missing required top-level key / empty `models` / non-numeric or negative rate raises); cost is `None` (not `0`) when a persona has no token telemetry, and a model that HAS tokens but no pricing entry raises loudly (`PricingTable.get`) rather than defaulting.
- **Method-comparison figure config:** `config/analysis/method_significance/comparison.json` -- drives the method-comparison significance figure/table emitted by `analyze_method_significance.py`. `pairs_mode` (one of `allowed_pairs_modes`: `adjacent` (default), `all`, `vs-baseline`, `significant-only`) selects which method pairs get a significance bracket; `star_thresholds` is the p-value -> star-symbol cutoff list (matched smallest-`max_p` first, first match wins) and `ns_symbol` the non-significant label (GraphPad/Prism convention). Loaded fail-fast by `analysis/method_significance/builder.py::load_comparison_config` (missing file / unknown `pairs_mode` / malformed shape raises); it knows nothing about models, countries, or matplotlib.
- **GUI config:** `config/gui/menu.yaml` + `config/gui/flows/*.yaml` -- the catalogue and per-flow round-trip YAML for the Flow Runner GUI (`gui`; see [gui Flow Runner](../development/gui.md))
